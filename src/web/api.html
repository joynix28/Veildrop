Why no API key?

Your 15-word recovery phrase is the key. The inbox ID is cryptographically derived from the phrase (SHA-256), so possession of the phrase proves ownership. Nothing to register, nothing to leak, nothing to rotate. You create the inbox with your phrase and read it back with the same phrase — even years later. A short access token is also issued at creation for convenience (no spaces to URL-encode).

1b. End-to-end encrypted inboxes (E2EE)

# Generate an RSA keypair client-side, wrap the private key with a key
# derived from your mnemonic (KEK = SHA-256 of the phrase), then send:
#   pubkey      = SPKI export, base64
#   privkey_enc = base64(iv) + ":" + base64(AES-GCM(KEK, PKCS8))
curl -X POST https://veildrop.fr/api/v1/inbox \
  -H "Content-Type: application/json" \
  -d '{"mnemonic":"abandon ability able ...","ttl":"1d","e2ee":true}'

# → {... "e2ee":true,"pubkey":"MIIBIjANBgkq...","privkey_enc":"QdFuF5...:9V4k..."}
# The server stores ONLY the public key + wrapped private key. Incoming emails
# are encrypted to your public key (encv2: format) before touching the database.
# Nobody — operator included — can decrypt without the mnemonic.

# Reading: list/detail responses include "e2ee":true and "privkey_enc".
# Unwrap the private key in your browser and decrypt each encv2: field:
#   encv2:<b64(RSA-OAEP(public, dataKey))>:<b64(iv)>:<b64(cipher)>
# Field = RSA-OAEP-unwrap(dataKey) then AES-256-GCM-decrypt(iv, dataKey, cipher).
curl -X GET "https://veildrop.fr/api/v1/mail?key=YOUR_TOKEN"
# Node.js example — decrypt a message with your mnemonic (WebCrypto, Node 22+)
import { webcrypto } from 'node:crypto';
const crypto = webcrypto; // global in Node 22
const MN = "your 15 words here".split(' ');
const b64 = (u) => Buffer.from(u).toString('base64');
const unb64 = (s) => new Uint8Array(Buffer.from(s, 'base64'));

const kek = await crypto.subtle.importKey('raw',
  new Uint8Array(await crypto.subtle.digest('SHA-256', new TextEncoder().encode(MN.join(' ')))),
  { name: 'AES-GCM' }, false, ['encrypt', 'decrypt']);

const res = await fetch(`https://veildrop.fr/api/v1/inbox/${INBOX_ID}/messages?key=${MN.join(' ')}`);
const data = await res.json();            // e2ee: true, privkey_enc: "iv:wrapped"
const [iv, wrapped] = data.privkey_enc.split(':');
const pkcs8 = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: unb64(iv) }, kek, unb64(wrapped));
const privKey = await crypto.subtle.importKey('pkcs8', pkcs8, { name: 'RSA-OAEP', hash: 'SHA-256' }, false, ['decrypt']);

async function decryptField(field) {
  if (!field || !field.startsWith('encv2:')) return field;
  const [_, dkw, iv2, ct] = field.split(':');
  const dk = await crypto.subtle.decrypt({ name: 'RSA-OAEP' }, privKey, unb64(dkw));
  const aesKey = await crypto.subtle.importKey('raw', dk, { name: 'AES-GCM' }, false, ['decrypt']);
  const plain = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: unb64(iv2) }, aesKey, unb64(ct));
  return new TextDecoder().decode(plain);
}
const m = data.messages[0];
console.log(await decryptField(m.subject), await decryptField(m.body_enc));
⚠️ Trade-offs: the server cannot scan E2EE mailboxes for abuse or malware, and the GDPR export returns raw encrypted data (plus your keys). Outgoing email is always plain SMTP. Two modes: let the server generate the keypair (send e2ee:true — the mnemonic transits at creation but is never stored), or generate the keypair yourself and send pubkey + privkey_enc (the mnemonic never touches the network, like the web client).

2. Read messages (read-once)

Read-once policy: the list returns metadata only (sender, subject, attachments, date — never the body). Opening a message delivers the full content and destroys it immediately. One read = one copy, guaranteed.

# One variable, that's all you ever need to paste:
KEY="51d5720a64aa494ab377f5c530a3f68e"

curl -H "X-API-Key: $KEY" https://veildrop.fr/api/v1/mail
# → {"address":"8f14e45fceea167a@veildrop.fr","messages":[{ "id":"...","from":"sender@x.com",
#      "subject":"Verify your account","has_attachments":false,"attachments":[],
#      "received_at":...,"is_read":false}],...}
# NO body in the list — bodies are only delivered by reading a message.

# Read once — returns the full message, then deletes it server-side:
curl -H "X-API-Key: $KEY" https://veildrop.fr/api/v1/mail/MESSAGE_ID
# → { ..., "body":"...", "body_html":"...", "attachments":[...], "deleted_after_read":true }

Privacy & security

  • No cookies, no analytics, no tracking, no JavaScript required.
  • The mnemonic is generated with cryptographic randomness; VeilDrop never stores it — only a hash of your access token is kept.
  • All SQL is parameterized; all inputs are validated, sanitized and length-capped; email headers are CRLF-stripped (no injection).
  • Messages are deleted on expiry; hard-purged from EU storage within 24 hours.
  • Mailboxes can be end-to-end encrypted (E2EE): emails are locked with your public key before touching the database — see §1b above.

Pourquoi pas d'API key ?

Votre phrase de récupération de 15 mots EST la clé. L'ID de la boîte est dérivé cryptographiquement de la phrase (SHA-256) : posséder la phrase prouve que vous êtes propriétaire. Rien à enregistrer, rien à fuiter, rien à faire tourner. Créez la boîte avec votre phrase, relisez-la avec la même phrase — même des années plus tard. Un jeton d'accès court est aussi délivré à la création pour plus de confort (pas d'espaces à encoder dans l'URL).
